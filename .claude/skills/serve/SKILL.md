# serve — публикация LOST через Cloudflare quick tunnel

Быстрый бесплатный способ выставить сайт в интернет с этого Mac: без домена и аккаунта.
Всю работу делают два скрипта в этой папке — скилл только их зовёт и докладывает адрес.

## Запуск

```
bash .claude/skills/serve/serve.sh
```

Скрипт идемпотентен и сам:
1. ставит `cloudflared` в `~/.local/bin`, если его нет;
2. поднимает контейнер (`docker compose up -d` в `web/`), если `/api/health` молчит;
3. снимает прошлый туннель и запускает новый;
4. печатает публичный адрес `https://<...>.trycloudflare.com`.

**Доложи пользователю ровно адрес** из последней строки (`🌐 ...`) — это и есть ссылка, которую он даёт людям.

## Снятие

```
bash .claude/skills/serve/stop.sh
```

Снимает только туннель, контейнер остаётся жить на `localhost:3000`. Погасить и контейнер —
`docker compose down` в `web/` (тома с базой и картинками при этом сохраняются).

## Что помнить самому

- **Это публичный доступ в интернет.** Публичная часть открыта всем; админка/студия/запись
  закрыты, пока в `web/.env` пуст `ADMIN_PASSWORD`. Нужен операторский доступ — задать пароль
  и `docker compose up -d` (пересоздаст контейнер под новый env).
- **Адрес случайный и меняется** при каждом перезапуске туннеля — это природа quick tunnel,
  не баг. Постоянный адрес — только через домен и именованный туннель (см. `DEPLOY.md`).
- Ссылка жива, пока включён Mac, healthy контейнер и процесс `cloudflared`. pid/лог/адрес —
  в `web/.cache/` (`tunnel.pid`, `tunnel.log`, `tunnel.url`, всё в `.gitignore`).
- Скрипт под macOS (бинарник `cloudflared` — darwin). На сервере туннель не нужен: там прямой
  порт за nginx/Caddy, вариант A в `DEPLOY.md`.
