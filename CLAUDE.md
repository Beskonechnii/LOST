# LOST — карта проекта

## Рабочие правила

- Пользователя зовут Стас (можно Стасон) — обращайся по имени.
- Мелкие правки делай напрямую: без plan mode, без Explore/Plan-сабагентов.
- Сабагентов запускай только если пользователь явно просит или задача реально широкая.
- Отвечай кратко, без пересказа того, что уже установлено.
- Модель по умолчанию — Sonnet; Opus — только под сложное и по запросу.

### Ритм работы над большими задачами

- **Один чат = один логический этап/фича.** Большую задачу дроби на этапы; каждый новый этап — новый чат,
  чтобы не раздувать контекст и не путаться.
- **Журнал — `WORKLOG.md` в корне.** В конце этапа дописывай туда короткую запись: дата, что сделано,
  какие файлы трогали (куда смотреть), что осталось / следующий шаг. Новый чат начинает с чтения последней записи.
- **Каждый чат закрывается коммитом и пушем** в рабочую ветку (скилл `ship`). Не оставляй незакоммиченное
  между чатами — следующая сессия должна видеть состояние в git, а не в голове.
- **Скилл `stage`** — этап по плану, не открывая новый чат: сабагент делает его в своём контексте,
  в чат возвращается короткий отчёт, затем `ship`. Новый чат по-прежнему чище (контекст с нуля),
  но `stage` дешевле и не требует переносить состояние руками. План активной задачи — `TOURNAMENTS-PLAN.md`.

## 1. Где что лежит

```
/                       доки + .claude/ (скиллы, launch.json)
└── web/                ВСЁ приложение. Работа над кодом идёт отсюда
    ├── prisma/         schema.prisma + миграции + dev.db (коммитится, см. §3)
    ├── data/           roster.json, snapshot.json (снимок БД), theme.json — коммитятся
    ├── scripts/        ручные утилиты (tsx), не часть рантайма
    ├── public/         assets/ (иконки Dota), templates/ (подложки), uploads/ (лого и фото)
    └── src/            app/ (роуты + API) · components/ui · lib/ (логика) · studio/ (движок графики)
```

Подробная карта — **`MAP.md`**: разделы приложения и их маршруты, ответственность каждого файла
в `src/lib/`, движок студии, скрипты наполнения ростера, перенос данных между устройствами.
**Читать перед тем, как искать файл** — там же сказано, куда писать новое.

Направление данных важное: **ростер — источник, студия и таблица — потребители.** Если студии
не хватает поля у команды/игрока — оно заводится в модели ростера, а не дублируется в payload шаблона.

Маршруты разделены на две группы: `src/app/(public)/` — продукт, `src/app/(admin)/` — всё, что пишет.
Группы на URL не влияют, у каждой свои layout и навигация. Почему так — «Продукт и служебная часть»
в `ARCHITECTURE.md`.

## 2. Запуск, команды, грабли

```bash
cd web && npm run dev
```

- Порт **3000**. Часто сервер уже запущен в другом окне — Next 16 не даёт поднять второй в той же папке.
- Проверка связки с БД: `GET /api/health` → `{ ok, teams, matches, points }`.
- `web/.env` (в `.gitignore`, шаблон — `web/.env.example`): `DATABASE_URL`, `OPENAI_API_KEY`,
  `STEAM_API_KEY`, `GOOGLE_CLIENT_ID/SECRET`, `OWNER_EMAIL`, `FRAME_ANCESTORS`, `AUTH_SECRET`.
  Без второго не работает `/studio/generate`; вход есть при `GOOGLE_CLIENT_*` (Google) **или** просто с
  `AUTH_SECRET` (email+пароль — без него сессии не подписываются); без `OWNER_EMAIL` некому раздавать
  роли и права; `FRAME_ANCESTORS` нужен только для встраивания в лендинг. Почтовых ключей больше нет —
  писем приложение не шлёт (`docs/archive/ACCOUNTS-PLAN.md` §2.4).
  Новая машина с нуля — `web/README.md`.
  **Ключи только в `.env`** — ни в коде, ни в коммитах, ни в чат.
- Типы: `npx tsc --noEmit`. Линт: `npm run lint`. Тестов в проекте нет.
  После переноса файлов между папками `.next/types/validator.ts` врёт устаревшими путями —
  лечится `rm -rf .next/types` перед проверкой типов.

**Prisma 7 (главные грабли):**
- `new PrismaClient()` без аргумента **не компилится** — нужен driver-adapter, используем `@prisma/adapter-libsql`.
- Клиент генерится в `src/generated/prisma`, импорт — `@/generated/prisma/client`.
- `DATABASE_URL` в `web/.env`, путь **относительный** к `web/` — абсолютный `file:`-URL ломает libsql на Windows.
- sqlite не умеет enum → строковые поля с комментарием-перечислением в схеме.

**Next.js 16 (Turbopack):** версия новее того, что агент «помнит». Перед написанием кода с непривычным API —
читать `web/node_modules/next/dist/docs/`, а не полагаться на память. Это же продублировано в `web/AGENTS.md`.

## 3. Конвенции

- **Комментарии и UI — по-русски.** Комментарий объясняет *почему*, а не пересказывает код; так написан весь проект.
- Слаг (`slug`) — ключ импорта **и** имя файла ассета. Одно имя связывает таблицу, БД и картинку.
  Поэтому картинка находится и без БД: `uploads.ts` подставит `<slug>-logo.png` там, где поле пустое.
- Скрипты в `scripts/` идемпотентны и запускаются руками; в рантайм-код их не тянуть.
  Читалка xlsx у них общая — `scripts/xlsx.ts` (ради гиперссылок ячеек: в CSV их нет).
- `public/uploads/` — ассеты релиза, коммитятся вместе с кодом (как и вендоренные иконки Dota).
  Исключения — `uploads/generated/` (генерации OpenAI) и `uploads/postgame/` (архив выгрузок):
  это вывод, а не ассеты релиза, обе в `.gitignore`.
- **`prisma/dev.db` коммитится.** Сетка встреч и правки результатов вводятся руками в UI — скриптами импорта
  их не восстановить, поэтому база едет в репозитории как ассет релиза. Мержить бинарник нельзя:
  работаем на одной машине за раз, `git pull` перед началом. Настройка новой машины — `web/README.md`.
- Стили — Tailwind v4, тёмная тема, акцент — фиолетовый (`violet-600`).

## 4. Документация

| Файл | О чём |
|---|---|
| **`MAP.md`** | структура: папки, разделы, слои `src/lib/`, студия, скрипты |
| **`BACKLOG.md`** | роадмап, долги в коде, открытые вопросы, кандидаты в скиллы |
| `ARCHITECTURE.md` | дев-спека: модель данных, флоу синка, реестр баллов + журнал решений с датами |
| `WORKLOG.md` | журнал работ, одна запись на этап, новейшее сверху |
| `TOURNAMENTS-PLAN.md` | активная задача: турниры и приём составов (этапы 1–5 сделаны) |
| `DEPLOY.md` | выкладка на сервер |
| `web/README.md`, `web/AGENTS.md` | первый запуск · жёсткие правила внутри `web/` |
| `docs/brand/` | `DOCS.md` (проект, партнёры, медиакит), `BRENDBOOK.md`, `COMPETITORS.md` |
| `docs/archive/` | закрытые планы (`ACCOUNTS-PLAN.md`) — как разбор принятых решений |

**Правило:** решение или новая подсистема → абзац в `ARCHITECTURE.md`; где лежит → строка в `MAP.md`;
что осталось сделать → пункт в `BACKLOG.md`. Открытые вопросы не живут в комментариях кода.
