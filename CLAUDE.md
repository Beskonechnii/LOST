# LOST — карта проекта

Это файл, который читают агенты в начале работы. Здесь — **где что лежит и кто за что отвечает**.
Подробности решений — в тематических доках (ссылки ниже), дублировать их сюда не надо.

**LOST (League of Spirit)** — киберспортивная студия по Dota 2 (Минск). Репозиторий — операционная система лиги:
одно Next.js-приложение, где данные лиги живут в БД, а поверх них работают отчёты по матчам, таблица и генерация графики.

---

```
    ├── public/
    │   ├── assets/     иконки Dota (heroes/items/abilities), вендорятся скриптом
    │   ├── templates/  подложки шаблонов графики: <templateId>/bg.png
    │   └── uploads/    лого и фото ростера — коммитятся; кроме generated/ (черновики OpenAI)
    │                   и postgame/ (архив выгруженных картинок матча)
    └── src/
        ├── app/        роуты (Next App Router) + API

```

## 2. Разделы приложения

Верхняя навигация — `src/app/_components/site-nav.tsx` (`SiteNav` — разделы, `SubNav` — подразделы секции).

| Раздел | Маршрут | Что делает | БД |
|---|---|---|---|
| **Матч** | `/` | Постгейм-отчёт по ID матча из OpenDota: скорборд, таланты, предметы, драфт, график золота. Выгруженные картинки ложатся в архив (файлы, не БД) | не трогает |
| **LOST D1** | `/standings`, `/standings/groups`, `/standings/playoff` | «Таблицы» — по группам, с зонами выхода; «Групповая стадия» — сетка встреч; «Плей-офф» — черновик сетки. Таблица считается из сетки, правка встречи двигает обе | читает + правит `GroupSeries` |
| **Ростер** | `/roster/teams`, `/roster/players`, карточки `<id>` (+`/edit`) | Справочник команд и игроков — **сюда пишут**. Карточки команды и игрока — витрины, формы вынесены на `/edit` | пишет |
| **Студия · Шаблоны** | `/studio` | Сборка графики по данным лиги — **только читает ростер** | читает + `Render` |
| **Студия · Генерация** | `/studio/generate` | Картинки по промту через OpenAI Images (платно) | не трогает |
| **Админка** | `/admin/login` | Вход по паролю (`ADMIN_PASSWORD`). Закрыто всё, что пишет: `/studio*`, `*/edit`, не-GET к `/api/*`. Публичная часть открыта | не трогает |

Направление данных важное: **ростер — источник, студия и таблица — потребители.** Если студии не хватает поля
у команды/игрока — оно заводится в модели ростера, а не дублируется в payload шаблона.

## 3. Ключевые слои (`src/lib/`)

| Файл | Ответственность |
|---|---|
| `prisma.ts` | singleton клиента. Prisma 7 требует driver-adapter — см. §5 |
| `auth.ts` | **только сервер**: защита админки — пароль из `ADMIN_PASSWORD`, подписанная кука и `needsAdmin()` (что закрыто). Развилка — `src/proxy.ts` |
| `opendota.ts` | всё общение с OpenDota + резолв id→имя через кэш констант. Самый большой файл, вся «грязь» протокола здесь |
| `steam-match.ts` | **только сервер**: запасной источник матча — Steam Web API (`STEAM_API_KEY`). Приводит ответ Valve к `RawMatch` и отдаёт в общую сборку из `opendota.ts` |
| `match-sync.ts` | `openDotaMatchId` → `MatchStat` + авто-победитель + подсказка MVP |
| `postgame-archive.ts` | **только сервер**: архив выгруженных постгеймов — PNG в `public/uploads/postgame` + подпись рядом. Истина о содержимом — файлы на диске, не БД |
| `assets.ts` | **единственное место**, где решается путь к иконке. Локально `/assets/<kind>/<slug>.png`, фолбэк — CDN Valve |
| `roles.ts` | список ролей. Порядок массива = порядок вывода состава везде. Роль в БД — строка-ключ |
| `profiles.ts` | `slugify()` (кириллица транслитом), пути к `public/uploads`, ссылки Dotabuff/Stratz/Steam из `accountId` (поля в БД их перекрывают). Здесь же разбор ввода анкеты: `accountIdFromUrl()` (ссылка на профиль → steam32), `normalizeTelegram()`, `parseBirthday()`, `playerGaps()` |
| `roster-data.ts` | выборки для страниц ростера (только чтение) + `teamMmr()` — MMR команды по основе |
| `uploads.ts` | **только сервер**: путь к лого/фото. Поле в БД — истина, иначе файл по конвенции `<slug>-<field>` из `public/uploads` |
| `roster-spots.ts` | правила состава: действующим (поз. 1–5) можно быть только в одной команде. Один источник для импорта и API |
| `studio-refs.ts` | те же данные, но в форме, которую ждут шаблоны (`TeamRef`/`PlayerRef`) |
| `standings.ts` | расчёт таблицы лиги. Standings **не хранятся**: групповая стадия + матчи + `PointsEntry` |
| `group-stage.ts` | **только сервер**: выборки групповой стадии (сетка встреч — единственный источник В/П/О) |
| `qualification.ts` | чистые правила без БД, можно на клиенте: `seriesPoints()` (2:0→3, 2:1→2, 1:2→1) и зоны выхода (1–4 верхняя, 5–6 нижняя, два последних — вылет) |
| `talents.json` | справочник талантов героев, собирается `scripts/build-talents.mjs` |
| `dota-constants.ts` + `.json` | вендоренные справочники Доты (герои, предметы, способности, баффы) — чтобы не ходить за ними в сеть. Собирается `scripts/build-dota-constants.mjs`, перезапускать при смене патча |
| `openai-images.ts` | **только сервер**: вызов OpenAI Images, читает `OPENAI_API_KEY`. Из клиентских компонентов не импортировать |
| `image-options.ts` | варианты настроек генерации (модели, размеры, качество) — чистые данные, можно на клиенте |

## 4. Движок студии (`src/studio/`)

**Шаблон = размер холста + декларативная схема полей + React-компонент.** Форма мастера строится из схемы
автоматически, поэтому **новый шаблон = файл в `templates/` + строка в `registry.ts`**, без новых страниц и форм.

| Файл | Роль |
|---|---|
| `types.ts` | контракт: `FieldDef` (text/select/team/player/group), `TemplateDef`, хелперы `asText/asTeam/asPlayer/asRows` |
| `registry.ts` | единственная точка регистрации шаблонов |
| `resolve.ts` | payload формы (id строкой) → развёрнутые объекты для рендера |
| `Canvas.tsx` | превью: натуральные пиксели под `transform: scale`, contain по обеим сторонам |
| `templates/parts.tsx` | общие куски шаблонов |

Страницы студии — в `src/app/studio/`: `page.tsx` (список), `new/[templateId]` (мастер),
`_components/wizard.tsx` (форма + превью + экспорт), `render/[templateId]` («голый» рендер),
`generate/` + `_components/generator.tsx` (генерация по промту — к движку шаблонов отношения не имеет).

Что важно помнить:
- **Превью и экспорт — один и тот же компонент.** Экспорт PNG клиентский (`modern-screenshot`), масштаб снимается
  на клоне → PNG выходит ровно `size.w × size.h`. Поэтому «что вижу — то и скачал»; не ломать этот инвариант.
- `/studio/render/[templateId]?p=<base64>` — рендер без интерфейса, задел под серверный скриншот (Playwright).
- Сохранённые генерации — модель `Render` (payload формы строкой), открываются обратно через `?render=<id>`.
- Подложки шаблонов — `public/templates/<id>/bg.png`. Файла нет → фирменный градиент-заглушка.

## 5. Запуск, команды, грабли

```bash
cd web && npm run dev
```

- Порт **3000**. Часто сервер уже запущен в другом окне — Next 16 не даёт поднять второй в той же папке.
- Проверка связки с БД: `GET /api/health` → `{ ok, teams, matches, points }`.
- `web/.env` (в `.gitignore`, шаблон — `web/.env.example`): `DATABASE_URL`, `OPENAI_API_KEY`,
  `STEAM_API_KEY`, `ADMIN_PASSWORD`. Без второго не работает `/studio/generate`; без последнего
  админка закрыта наглухо (это не баг, а дефолт). Новая машина с нуля — `web/README.md`.
  **Ключи только в `.env`** — ни в коде, ни в коммитах, ни в чат.
- Типы: `npx tsc --noEmit`. Линт: `npm run lint`. Тестов в проекте нет.

**Prisma 7 (главные грабли):**
- `new PrismaClient()` без аргумента **не компилится** — нужен driver-adapter, используем `@prisma/adapter-libsql`.
- Клиент генерится в `src/generated/prisma`, импорт — `@/generated/prisma/client`.
- `DATABASE_URL` в `web/.env`, путь **относительный** к `web/` — абсолютный `file:`-URL ломает libsql на Windows.
- sqlite не умеет enum → строковые поля с комментарием-перечислением в схеме.

**Next.js 16 (Turbopack):** версия новее того, что агент «помнит». Перед написанием кода с непривычным API —
читать `web/node_modules/next/dist/docs/`, а не полагаться на память. Это же продублировано в `web/AGENTS.md`.

## 7. Наполнение ростера (три шага)

```bash
npx tsx scripts/sheet-to-roster.ts --sheet "<ссылка на таблицу>"   # → data/roster.json
npx tsx scripts/import-roster.ts                                    # → БД, upsert по slug
npx tsx scripts/import-media.ts --from "<папка>"                    # лого/фото по имени файла = slug
npx tsx scripts/import-crm.ts --file "<выгрузка.xlsx|csv|json>" --dry   # анкеты из CRM в уже заведённых игроков
```

Берётся **xlsx**-экспорт, не CSV: ссылки на профили — гиперссылки ячеек, в CSV их нет.
Есть готовый скилл `roster-sync` — он это и делает. Второй скилл, `ship`, — коммит и пуш.

## 8. Конвенции

- **Комментарии и UI — по-русски.** Комментарий объясняет *почему*, а не пересказывает код; так написан весь проект.
- Слаг (`slug`) — ключ импорта **и** имя файла ассета. Одно имя связывает таблицу, БД и картинку.
  Поэтому картинка находится и без БД: `uploads.ts` подставит `<slug>-logo.png` там, где поле пустое.
- Скрипты в `scripts/` идемпотентны и запускаются руками; в рантайм-код их не тянуть.
  Читалка xlsx у них общая — `scripts/xlsx.ts` (ради гиперссылок ячеек: в CSV их нет).
- `public/uploads/` — ассеты релиза, коммитятся вместе с кодом (как и вендоренные иконки Dota).
  Исключения — `uploads/generated/` (генерации OpenAI) и `uploads/postgame/` (архив выгрузок):
  это вывод, а не ассеты релиза, обе в `.gitignore`.
- **`prisma/dev.db` коммитится.** Сетка встреч и правки результатов вводятся руками в UI — скриптами импорта
  их не восстановить, поэтому база едет в репозитории как ассет релиза. Мержить бинарник нельзя:
  работаем на одной машине за раз, `git pull` перед началом. Настройка новой машины — `web/README.md`.
- Стили — Tailwind v4, тёмная тема, акцент — фиолетовый (`violet-600`).

  в одной команде» проверяется на импорте. Разбор — в `ARCHITECTURE.md`.
- Не сделано: реестр начисления баллов (модель `PointsEntry` есть, UI нет).
