# LOST — карта проекта

# Рабочие правила

- Мелкие правки делай напрямую: без plan mode, без Explore/Plan-сабагентов.
- Сабагентов запускай только если пользователь явно просит или задача реально широкая.
- Отвечай кратко, без пересказа того, что уже установлено.
- Модель по умолчанию — Sonnet; Opus — только под сложное и по запросу.

## 2. Разделы приложения

Маршруты разделены на две группы: **`src/app/(public)/`** — продукт (его видит посетитель) и
**`src/app/(admin)/`** — служебная часть (всё, что пишет). Группы на URL не влияют, у каждой свои
layout, навигация и метаданные. Почему так, а не отдельным репозиторием — «Продукт и служебная
часть» в `ARCHITECTURE.md`.

Навигация — `src/app/_components/site-nav.tsx`. Верхняя строка **единая на весь сайт**: две вкладки
рядом — `LOST S2` (продукт) и `Админ` (операторская); `PublicNav` и `AdminNav` рисуют её одинаково,
разными их держит лишь то, что зовут разные layout'ы. `SubNav` — второй ряд подвкладок: `SeasonNav`
под `LOST S2` (дивизионы + ростер), `AdminSubNav` под `Админ` (UNDERBEER 2.0, Архив серий, Студия,
Матч, 1х1, fearless draft). **Матч живёт в группе `(admin)`** — перенесён под вкладку «Админ» и
закрыт паролем наравне со студией; с лендинга его убрали.

| Раздел | Маршрут | Что делает | БД |
|---|---|---|---|
| **Лендинг** | `/` | Входная дверь продукта: кто такие, цифры сезона, карточки разделов. Цифры считаются из базы, не вписаны руками | читает (`count`) |
| **Матч** | `/match`, `/match/[id]` (группа `(admin)`) | Постгейм-отчёт по ID матча из OpenDota: скорборд, таланты, предметы, драфт, график золота. У отчёта постоянная ссылка — состояние (источник, вкладка, названия команд) живёт в query. Архив выгруженных картинок (файлы, не БД) виден только вошедшему. Живёт под вкладкой «Админ» и **закрыт паролем** (`/match` в `PROTECTED_PAGES`) | не трогает |
| **Карта вардов** | `/admin/vision` (группа `(admin)`) | Расстановка вардов команды по всем её картам из архива: выбор команды → сводное наложение + каждая карта с полоской времени (10-мин деления, 0:00 = вся расстановка). Данные в БД (`Ward`), строится офлайн | читает `Ward` |
| **LOST D1 / D2** | `/standings/[div]` (`d1`/`d2`) + `/groups`, `/playoff`, `/stats` | Раздел дивизиона: «Таблицы» — по группам, с зонами выхода; «Групповая стадия» — сетка встреч; «Плей-офф» — черновик сетки; «Статистика» — рейтинги игроков и команд, разрез (стадия + группа или половина сетки) живёт в query. Один шаблон на оба дивизиона, дивизион в URL; голый `/standings` → редирект на `d1`. Справочник дивизионов — `src/lib/divisions.ts` | читает + правит `Series` |
| **Ростер** | `/roster/teams`, `/roster/players`, карточки `<id>` | Публичные витрины команд и игроков. Формы создания и операторская диагностика (пробелы в анкетах, `slug`) видны только вошедшему — `isAdmin()` из `src/lib/admin-session.ts` | читает |
| **Встреча** | `/series/<slug>` | Публичная страница серии: счёт, карты одна под другой, у каждой оба состава с героями и K/D/A. Форма — с разбора серии на Dotabuff; детали карты не дублирует, ведёт в `/match/<id>`. Ключ в адресе — слаг (`guzliki-vs-from-paris`), а не `id`: `id` после `db:import` другой | читает |
| **Архив серий** | `/admin/series` | Встречи турнира (группа и плей-офф) и карты в них: завести, привязать/отцепить/перечитать карту, удалить встречу. Фильтр по разрезам (группа A/B, верхняя/нижняя сетка, гранд-финал). **Единственный вход в архив**: привязка карты сразу читает стату, из неё считается «Статистика» дивизиона | пишет `Series` + `Match` + `MatchStat` |
| **Правка ростера** | `/admin/roster/{teams,players}/<id>/edit` | Формы — **сюда пишут**. Живут в `(admin)`, поэтому граница видна прямо в URL | пишет |
| **Студия · Шаблоны** | `/studio` | Сборка графики по данным лиги — **только читает ростер** | читает + `Render` |
| **Студия · Генерация** | `/studio/generate` | Картинки по промту через OpenAI Images (платно) | не трогает |
| **UNDERBEER 2.0** | `/underbeer`, `/underbeer/<id>` | Шоу-драфт: капитаны по очереди (змейка) собирают команды из ростера, у каждой по разу «закрепить»/«украсть». Состояние — `DraftSession.payload` JSON. Операторское, за паролем | читает ростер + `DraftSession` |
| **Оверлей драфта** | `/overlay/underbeer/<id>` | «Голый» публичный рендер результата драфта для OBS-сцены — без навигации и пароля (группа `(bare)`) | читает |
| **1х1 / fearless draft** | `/admin/1x1`, `/admin/fearless-draft` | Заглушки будущих инструментов админки («в разработке»). Держат место в ряду `Админ`; общий компонент `WorkInProgress` в `(admin)/_components/wip.tsx` | не трогает |
| **Админка** | `/admin/login` | Вход по паролю (`ADMIN_PASSWORD`). Закрыто всё, что пишет: `/studio*`, `/admin*`, `/underbeer*`, `/match*`, не-GET к `/api/*`. Публичная часть открыта | не трогает |

Направление данных важное: **ростер — источник, студия и таблица — потребители.** Если студии не хватает поля
у команды/игрока — оно заводится в модели ростера, а не дублируется в payload шаблона.

## 3. Ключевые слои (`src/lib/`)

| Файл | Ответственность |
|---|---|
| `prisma.ts` | singleton клиента. Prisma 7 требует driver-adapter — см. §5 |
| `auth.ts` | **только сервер**: защита админки — пароль из `ADMIN_PASSWORD`, подписанная кука и `needsAdmin()` (что закрыто). Развилка — `src/proxy.ts` |
| `admin-session.ts` | **только сервер**: `isAdmin()` для серверных компонентов — «показывать ли операторские куски на публичной странице». Отдельно от `auth.ts`, потому что `next/headers` нельзя тянуть в `proxy.ts` |
| `opendota.ts` | всё общение с OpenDota + резолв id→имя через кэш констант. Самый большой файл, вся «грязь» протокола здесь |
| `match-api.ts` | **только сервер**: общий обработчик обоих роутов отчёта — порядок «проверить id → кэш → лимит → сеть». Кэш и лимит в двух копиях разъехались бы |
| `match-cache.ts` | **только сервер**: кэш собранных отчётов, файл на матч в `web/.cache/matches` (в `.gitignore`). Распарсенный отчёт неизменен → живёт вечно, остальные час |
| `rate-limit.ts` | **только сервер**: окно запросов по IP. Расходуют его **только промахи кэша** — отдача с полки бесплатна |
| `steam-match.ts` | **только сервер**: запасной источник матча — Steam Web API (`STEAM_API_KEY`). Приводит ответ Valve к `RawMatch` и отдаёт в общую сборку из `opendota.ts` |
| `match-sync.ts` | **только сервер**: отчёт матча → `MatchStat` + `Ward` (расстановка вардов) + длительность + авто-победитель + подсказка MVP. Отчёт берёт из `match-api.ts`, то есть из того же кэша, что и постгейм |
| `vision.ts` | **только сервер**: «карта вардов команды» из архива — команды с вардами, список карт команды, вижн одной карты. Читает `Ward` (пишется в `match-sync`), имена героев по slug через `heroBySlug` из `opendota.ts` |
| `scoreboard.ts` | **только сервер**: сборка `ScoreBoard` карты для шаблона `postgame-board` — отчёт (`loadMatchReport`, с предметами) + лого/цвета из ростера. Кормит поле `kind:"match"` студии |

| `leaders.ts` | **только сервер**: рейтинги турнира из `MatchStat`. Ничего не хранит — суммирует в памяти по фильтру «дивизион / стадия / группа» |
| `stages.ts` | стадии турнира (`group`/`playoff`), половины сетки (`upper`/`lower`/`grand`), раунды плей-офф и `CUTS` — разрезы, которыми режут архив и статистику. Без БД, годится на клиенте — как `divisions.ts` |
| `postgame-archive.ts` | **только сервер**: архив выгруженных постгеймов — PNG в `public/uploads/postgame` + подпись рядом. Истина о содержимом — файлы на диске, не БД |

## 4. Движок студии (`src/studio/`)

**Шаблон = размер холста + декларативная схема полей + React-компонент.** Форма мастера строится из схемы
автоматически, поэтому **новый шаблон = файл в `templates/` + строка в `registry.ts`**, без новых страниц и форм.

| Файл | Роль |
|---|---|
| `types.ts` | контракт: `FieldDef` (text/select/team/player/match/group), `TemplateDef`, `ScoreBoard`, хелперы `asText/asTeam/asPlayer/asBoard/asRows` |
| `registry.ts` | единственная точка регистрации шаблонов |
| `resolve.ts` | payload формы (id строкой) → развёрнутые объекты для рендера. Поле `match` разворачивается через `Refs.boards` (скорборд карты, см. `lib/scoreboard.ts`) |
| `Canvas.tsx` | превью: натуральные пиксели под `transform: scale`, contain по обеим сторонам |
| `templates/parts.tsx` | общие куски шаблонов |

Страницы студии — в `src/app/studio/`: `page.tsx` (список), `new/[templateId]` (мастер),
`_components/wizard.tsx` (форма + превью + экспорт), `render/[templateId]` («голый» рендер),
`generate/` + `_components/generator.tsx` (генерация по промту — к движку шаблонов отношения не имеет).

Что важно помнить:
- **Превью и экспорт — один и тот же компонент.** Экспорт PNG клиентский (`modern-screenshot`), масштаб снимается
  на клоне → PNG выходит ровно `size.w × size.h`. Поэтому «что вижу — то и скачал»; не ломать этот инвариант.
- `/studio/render/[templateId]?p=<base64>` — рендер без интерфейса, задел под серверный скриншот (Playwright).
- Сохранённые генерации — модель `Render` (payload формы строкой), открываются обратно через `?render=<id>`.
- Подложки шаблонов — `public/templates/<id>/bg.png`. Файла нет → фирменный градиент-заглушка.

## 5. Запуск, команды, грабли

```bash
cd web && npm run dev
```

- Порт **3000**. Часто сервер уже запущен в другом окне — Next 16 не даёт поднять второй в той же папке.
- Проверка связки с БД: `GET /api/health` → `{ ok, teams, matches, points }`.
- `web/.env` (в `.gitignore`, шаблон — `web/.env.example`): `DATABASE_URL`, `OPENAI_API_KEY`,
  `STEAM_API_KEY`, `ADMIN_PASSWORD`, `FRAME_ANCESTORS`. Без второго не работает `/studio/generate`;
  без `ADMIN_PASSWORD` админка закрыта наглухо (это не баг, а дефолт); `FRAME_ANCESTORS` нужен
  только для встраивания в лендинг. Новая машина с нуля — `web/README.md`.
  **Ключи только в `.env`** — ни в коде, ни в коммитах, ни в чат.
- Типы: `npx tsc --noEmit`. Линт: `npm run lint`. Тестов в проекте нет.
  После переноса файлов между папками `.next/types/validator.ts` врёт устаревшими путями —
  лечится `rm -rf .next/types` перед проверкой типов.

**Prisma 7 (главные грабли):**
- `new PrismaClient()` без аргумента **не компилится** — нужен driver-adapter, используем `@prisma/adapter-libsql`.
- Клиент генерится в `src/generated/prisma`, импорт — `@/generated/prisma/client`.
- `DATABASE_URL` в `web/.env`, путь **относительный** к `web/` — абсолютный `file:`-URL ломает libsql на Windows.
- sqlite не умеет enum → строковые поля с комментарием-перечислением в схеме.

**Next.js 16 (Turbopack):** версия новее того, что агент «помнит». Перед написанием кода с непривычным API —
читать `web/node_modules/next/dist/docs/`, а не полагаться на память. Это же продублировано в `web/AGENTS.md`.

## 7. Наполнение ростера (три шага)

```bash
npx tsx scripts/sheet-to-roster.ts --sheet "<ссылка на таблицу>"   # → data/roster.json
npx tsx scripts/import-roster.ts                                    # → БД, upsert по slug
npx tsx scripts/import-media.ts --from "<папка>"                    # лого/фото по имени файла = slug
npx tsx scripts/import-crm.ts --file "<выгрузка.xlsx|csv|json>" --dry   # анкеты из CRM в уже заведённых игроков
npx tsx scripts/resolve-vanity.ts --dry                             # steamcommunity.com/id/<имя> → account_id (нужен STEAM_API_KEY)
```

Игрок без `account_id` не попадает ни в один архив матча — его просто некем опознать. Ссылки на
Dotabuff/Stratz/OpenDota и `profiles/<steam64>` разбираются на лету (`playerAccountId` в
`src/lib/profiles.ts`), а именной адрес Steam превращает в число только `resolve-vanity`.

Берётся **xlsx**-экспорт, не CSV: ссылки на профили — гиперссылки ячеек, в CSV их нет.
Есть готовый скилл `roster-sync` — он это и делает. Второй скилл, `ship`, — коммит и пуш.

## 7.1 Перенос данных между устройствами

`dev.db` в `.gitignore`, поэтому состояние лиги ездит снимком `data/snapshot.json` (он **коммитится**):

```bash
npm run db:export   # БД → снимок. Делать перед коммитом, если правил данные в UI
npm run db:import   # снимок → БД. Делать после git pull
```

Импорт — **зеркало**: база становится копией снимка, лишнее удаляется (список печатается, есть `--dry`).
Снимок версионируется (`version`, сейчас **6**); старую версию импорт не чинит, а отвергает — пересними базу
свежим экспортом там, где данные актуальны. Перед записью импорт печатает, где строк в снимке
**меньше**, чем в базе — молча потерять руками введённую сетку встреч он не должен.
Связи в снимке идут по `slug`, а не по id: id автоинкрементные и на разных машинах разные. Разбор — в
`ARCHITECTURE.md` («Решение: снимок БД в git»).

## 8. Конвенции

- **Комментарии и UI — по-русски.** Комментарий объясняет *почему*, а не пересказывает код; так написан весь проект.
- Слаг (`slug`) — ключ импорта **и** имя файла ассета. Одно имя связывает таблицу, БД и картинку.
  Поэтому картинка находится и без БД: `uploads.ts` подставит `<slug>-logo.png` там, где поле пустое.
- Скрипты в `scripts/` идемпотентны и запускаются руками; в рантайм-код их не тянуть.
  Читалка xlsx у них общая — `scripts/xlsx.ts` (ради гиперссылок ячеек: в CSV их нет).
- `public/uploads/` — ассеты релиза, коммитятся вместе с кодом (как и вендоренные иконки Dota).
  Исключения — `uploads/generated/` (генерации OpenAI) и `uploads/postgame/` (архив выгрузок):
  это вывод, а не ассеты релиза, обе в `.gitignore`.
- **`prisma/dev.db` коммитится.** Сетка встреч и правки результатов вводятся руками в UI — скриптами импорта
  их не восстановить, поэтому база едет в репозитории как ассет релиза. Мержить бинарник нельзя:
  работаем на одной машине за раз, `git pull` перед началом. Настройка новой машины — `web/README.md`.
- Стили — Tailwind v4, тёмная тема, акцент — фиолетовый (`violet-600`).

## 9. Открытые вопросы

- **Сезон в составе.** Связь «состав» (`RosterSpot`) сделана, но сезона в ней нет — история составов между
  сезонами пока не хранится. В базе **Division 1 и Division 2** (залиты 28.07.2026). Инвариант «действующий
  только в одной команде» смягчён до **одной команды на дивизион**: игрок может быть действующим и в D1, и в
  D2 (их турниры раздельны) — проверка сравнивает `Team.group`. Разбор — в `ARCHITECTURE.md`.
- Не сделано: реестр начисления баллов (модель `PointsEntry` есть, UI нет).
- **Какой VPS.** Что нужен живой Node — решено (`ARCHITECTURE.md`, «Продукт и служебная часть»),
  площадка — нет.
- **Кто главный по базе.** Как только публичный сервер заработает, `prisma/dev.db` в репозитории
  начнёт расходиться с боевым. Развилка описана в `DEPLOY.md`, но не выбрана.
- **OG-картинки при шеринге.** У отчёта появилась постоянная ссылка, а превью для соцсетей нет:
  генератор постгейма клиентский (`modern-screenshot`), для серверной OG нужна отдельная реализация.
