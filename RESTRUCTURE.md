## Зачем это всё

Приложение выросло как **инструмент оператора, у которого есть публичные страницы**. Нужно
обратное: **продукт, у которого есть админка**. Публичная часть должна жить на сайте — либо
ссылками с основного лендинга, либо через `iframe` с нашего же сервера.

Диагноз был не в коде: слои разложены нормально, `needsAdmin()` — единственное место правды.
Ошибка в форме — входная дверь `/` это поле ввода ID матча, в меню торчала студия, у отчёта
не было постоянной ссылки.

## Решения (приняты, не пересматривать без повода)

| Решение | Почему так, а не иначе |
|---|---|
| **Route-группы в одном приложении**, не отдельный репозиторий | Публичная часть читает ровно то, что пишет внутренняя. Два репозитория — либо общая БД (тогда это не разделение), либо API-контракт. Плюс `opendota.ts`, `standings.ts`, постгейм-блоки и 58 МБ иконок уехали бы в копию, которая разойдётся за месяц |
| **Продукт = вся публичная часть**: разбор матча, таблица, витрина ростера | Решено с заказчиком |
| **Постгейм — публичный сервис со свободным вводом ID**, не только матчи лиги | Решено с заказчиком. Тянет за собой кэш, лимиты и постоянные ссылки — см. шаг 2–3 |
| **Правка ростера — на `/admin/roster/*`** | Граница «читают/пишут» становится видна прямо в URL. Позволило выкинуть правило `endsWith("/edit")` из `needsAdmin()` |
| **Хостинг — живой Node (VPS)**, статикой не обойтись | Все публичные страницы кроме постгейма — `force-dynamic` из sqlite. Обвязка (Docker, Caddy) уже написана, см. `DEPLOY.md` |

**Что это значит для интеграции на сайт.** Приложение живёт на поддомене (`app.leagueofspirits.ru`),
основной сайт ссылается на него или встраивает разделы через `iframe`. Оба способа доступны
одновременно. Статический экспорт таблицы (`scripts/build-standings-site.ts`) **не выбрасывать** —
это запасной путь, единственный работающий вообще без сервера.

### Что всплыло по дороге (важно помнить)

**Витрины ростера писали в БД.** `CreateForm` стоял прямо на страницах, которые стали публичными.
Появился `src/lib/admin-session.ts` — `isAdmin()` для серверных компонентов. Вынесен отдельно от
`auth.ts` намеренно: `auth.ts` импортирует `src/proxy.ts`, а `next/headers` туда тянуть нельзя.

**Операторская диагностика торчала наружу** — счётчики «без account_id» и «с неполной анкетой»,
подписи `нет: ...` на карточках, янтарные рамки, служебный `slug` в профиле. Всё спрятано за `isAdmin()`.
**При добавлении новых полей на витрины проверять: это факт о лиге или состояние наших данных?**

## Шаг 2 — постоянные ссылки на отчёт

Сейчас `src/app/(public)/page.tsx` — клиентский SPA на 809 строк, состояние живёт в `useState`,
поделиться отчётом нельзя.

- Постгейм переезжает с `/` на **`/match`** (форма ввода) и **`/match/[id]`** (сам отчёт).
- `/` освобождается под лендинг (шаг 4).
- Состояние переезжает в URL. Компоненты (`_components/postgame/*`, `match-archive.tsx`) не трогать —
  меняется только то, откуда берётся id и куда пишется результат.
- Архив выгруженных PNG (`match-archive.tsx`) — операторский инструмент. **Решить: прятать за
  `isAdmin()` или оставить публичным.** Скорее прятать: это полка черновиков оператора.

## Шаг 3 — кэш и лимиты (без этого сервис ляжет)

- **Кэш отчётов — обязателен.** У OpenDota лимит порядка 60 запросов в минуту на всех.
  Публичный трафик выест его сразу и заодно уронит внутренний разбор.
  Спасает то, что **отчёт по завершённому матчу неизменен** — кэшируется навсегда, без инвалидации.
- **Лимит по IP** на `/api/opendota/match/[id]` и `/api/steam/match/[id]` — иначе один скрипт
  сожжёт общий лимит и подставит `STEAM_API_KEY`.
- Заодно: **заголовки для `iframe`** (`frame-ancestors` со списком доменов основного сайта).
  Сейчас их нет — встраивание браузер заблокирует.

## Открытые вопросы

- **Какой VPS.** Факт «нужен живой Node» решён, площадка — нет.
- **Кто главный по базе.** Как только публичный сервер заработает, `prisma/dev.db` в репозитории
  начнёт расходиться с боевым. Развилка описана в `DEPLOY.md`, но не выбрана.
- **OG-картинки при шеринге.** Генератор постгейма клиентский (`modern-screenshot`), для серверной
  OG нужна отдельная реализация. Отложено.
- **Ветки.** `main` и `dev` отстают от `feature/studio`. Разбирать отдельно, не переключаться.
